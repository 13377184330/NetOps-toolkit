# NetOps Toolkit v4.1 - 网络运维工具集

一个功能强大、现代化界面的**多品牌交换机配置生成 + 真机运维 + AI 自然语言运维工具集**：华为/H3C/锐捷/迈普四品牌配置生成（Console 采集另支持思科识别），内置 11+ 网络工具，基于 Python + PyQt5 开发，**内网离线可用**（0 遥测、核心流程零网络调用）。

---

## 二开说明（Fork）

> 本仓库 Fork 自 [cooltea521/NetOps-toolkit](https://gitee.com/cooltea521/NetOps-toolkit)（MIT 协议）。
> 二开定位：**保持上游"绿色离线桌面工具"形态不变**，补齐它没有的"真机运维"能力——上游只做配置文本生成，本仓库补上连接真机之后的闭环（设备管理 / 连通测试 / 命令执行 / 配置下发 / 配置备份）。

### 新增能力

- **AI 运维（v4.1 新增）**：自然语言运维三模式——**生成配置 / 诊断分析 / 自由问答**。大模型接 OpenAI 兼容 API（DeepSeek / 智谱 GLM / 通义 / Moonshot / OpenAI / 本地 Ollama / 本地 vLLM 任选，设置→AI 一页配齐，API Key 本机 Fernet 加密存储），SSE 流式逐字渲染不冻结画面。**安全闭环（HITL）**：AI 只生成命令草稿、永不直接触达设备——命令进「待确认队列」（风险三级徽标：只读安全/写配置/高危，高危红字标亮，复用配置语法纠错引擎逐条体检），人工逐条勾选 → 下发确认弹窗（命令全文 + 高危横幅 + 责任勾选不勾选无法确认）→ 才走真机下发（默认不存盘，验收后人工 save）。诊断分析模式粘贴设备回显/日志让 AI 定位异常，只允许产出只读验证命令。**离线降级**：AI 不可用/未配置时生成配置模式自动退回离线规则引擎（自然语言生成工具同源），工具永远可用。安全架构参考开源项目 [Netiarius](https://github.com/Joeen-AI-Labs/Netiarius)（MIT）的 plan/confirm 人机回环范式，特此致谢
- **Console 只读采集可视化**：插 Console 线自动识别串口/厂商（华为/H3C/锐捷/迈普/思科 banner+提示符+版本三重识别），一键只读抓取 running-configuration + **LLDP 邻居 / MAC 地址表 / ARP 表 / 端口链路状态**四表联采；**分层可视化树**（基本信息 / 接口 / VLAN / 路由 / 安全）+ **配置健康度体检**（本地规则，评分与严重/警告/提示分级）。采集保真：串口会话硬化（提示符同步、写超时、静默判定），设备异步日志混入抓取窗口时如实提醒而非静默污染解析（真机实测踩中过），连续多次采集逐字节一致。**只读红线**：连接层命令白名单（仅 display/show），system-view/save/undo 等写命令架构级拦截；More 翻页空格续读、逐字符发送防吞、等待静默防竞争等串口踩坑全解
- **网络拓扑自动呈现**：采集后自动成图——本机交换机、本机 PC（含接入端口定位，终端换口后陈旧 MAC 残留自动按链路 UP 口修正）、LLDP 邻居（含带外管理口 MGE 链路）、终端（PC 不应答 LLDP，靠 MAC 表发现 + ARP 补 IP）、未识别设备（链路 UP 但对端无 LLDP/无 MAC——哑交换机或对端未开 LLDP，如实标注不略过）；NULL0/SVI 等逻辑口不渲染为设备。交互：拖动/缩放/自动布局、设备面板（双击/右键）、端口一览表（状态/VLAN/描述/下挂终端）、Ping、配置备份
- **拓扑页端口配置生成器**：多端口 Access/Trunk 批量生成，选中端口的当前 VLAN 自动预填（全一致才填、读不到不猜），纯命令复制（无注释）/送往下发闭环
- **设备面板（可视化俊瓜式配置）**：把交换机画成大号真实面板——端口矩阵方块（颜色即状态：绿=UP/灰=DOWN/紫=Trunk/红=shutdown，蓝点=下挂终端/紫点=LLDP 邻居，小字显示当前 VLAN，按 GE 电口/10GE 光口分组）；点端口右侧回显当前值，改参数（模式/VLAN 快选/描述/开关端口）底部命令**实时生成**（所见即所得，不懂语法也能改）；Ctrl 多选批量；非法参数即时红边+告警；面板选中端口 ↔ 拓扑图联动高亮，面板关闭自动还原；一键应用填入 Console 原文走下发确认闭环（取消保留面板继续调，确认后自动重采）。三入口：工具栏/设备面板动作集/右键菜单。对标 eSight/IMC/Prime 的设备面板视图，但无需建网管平面，插 Console 线即可用
- **设备运维面板**：设备清单管理（SSH 凭据本地 Fernet 加密）、真机连通测试（TCP 探测 + SSH 登录验证）、命令执行、配置下发、一键备份 running-config（版本化 + Diff）
- **自由终端（Console 交互式终端）**：像 SecureCRT 一样直接敲命令、实时回显——独立页签，串口 IO 全部收敛在单一后台线程（读回显/逐字符发送防吞/More 自动翻页可关）；命令历史 ↑↓ 翻、高频查询快捷键（当前配置/版本，按已识别厂商出对应语法）；拔线/驱动卡死发 IO 异常自动复位 UI 不卡"已连接"。**只读红线语义不变**：默认只读模式（同一套 check_read_only 白名单，display/show 前缀优先放行——display interface brief / saved-configuration 不再被关键字误拦），写命令须显式开启写模式（危险确认弹窗默认落在否、顶部红色警示横幅常驻、断开连接自动复位只读）；多行配置批量下发仍走 Console 可视化页的确认闭环
- **减少人工操作**（内网场景：能读到的信息不让人填）：Console 采集**一键存入设备清单**（名称/厂商/型号/管理 IP 自动预填，人只补 SSH 凭据，重复登记自动拦截）；VLAN 配置页**从采集选择端口**（真实端口名多选批量加入，不手敲）；端口配置 VLAN 预填（见上）
- **批量能力**：线程池批量探测/批量下发，进度实时回显，SSH/串口操作后台线程化不卡 UI
- **现代 UI 重做**：无边框圆角窗口（红黄绿圆点标题栏、可拖动、边缘缩放）、全局 QSS 重绘（中性细边框 + 聚焦反馈 + 明显圆角 + 字号层级）、卡片轻阴影、**可折叠卡片分层**（每页默认只展开首张卡片）、深色 IDE 风配置预览；Console 页原文与日志左右并列可拖分隔条（6:4，日志列加可读下限），下发按钮 2×2 网格防挤压
- **主题引擎**：浅色/深色双主题（设置里一键切换，全库 30+ 模块从内联色值迁到声明级重映射——Python 手绘色走 theme.t()，QSS 走词汇表翻译，切换后主窗口/启动页/所有对话框即时重绘）；统一对话框基建（BaseDialog 骨架 + primary/secondary/ghost/danger 四档语义按钮 + 统一样式消息框，终结弹窗风格各自为政）
- **窗口尺寸记忆**：默认 1200×740，用户拖动调整后自动记住
- **启动提速**：启动动画从 ~1.7s 压缩到 ~0.5s

### 离线可用性（内网友好）

> v4.1 起「AI 运维」页为可选联网能力：不配置任何模型时该页降级为离线规则引擎驱动，其余功能维持零网络调用不变；模型可接本地 vLLM/Ollama 实现全程不出内网。

- **0 遥测 / 0 更新检查 / 0 崩溃上报**，核心流程（采集 / 解析 / 拓扑 / 生成 / 体检）**零网络调用**
- 全库网络调用审计仅 4 处，全部在用户主动发起的工具内（TCP 探测 / HTTP 检测 / 公网 IP 查询 / MAC 本地库为纯离线），断网失败均优雅降级
- 回归矩阵含「全程 0 对外 TCP 连接」断言，逐轮真机验证

### 二开修复的问题

上游代码问题：

- `modules/vlan_config.py`：STP 生成 `stp mode {mode}` 缺 f 前缀，变量不替换
- `gui/tabs` 全部页签缺 `clear_config` 接口契约（新增页签时窗口启动即崩）
- 移除误提交的 `__pycache__`，补充 `.gitignore`
- `run.bat` 在中文路径下提前告警（PyQt5/Qt 5.15.2 平台插件在非 ASCII 路径下无法加载）

真机实测缺陷（多数为新设备/新场景才暴露的老问题）：

- **堆叠(IRF) 误判**：出厂单机自带 `irf auto-update enable` 等默认行被当成“堆叠启用”（两台 H3C 均中招）；改为 `irf-port` 成员绑定段 / MAD 配置才算启用
- **Ten-GigabitEthernet 端口全名双重展开**：短名展开表缺带连字符全名分支，`Ten-GigabitEthernet1/0/27` 被展开成 `Ten-GigabitEthernetn-GigabitEthernet1/0/27`（GE 口不含该前缀所以从未暴露，Ten-GE 口一选即中）
- **双击设备面板后鼠标抓取残留**：模态面板吃掉双击的尾随 release，场景 mouse grabber 不释放，关面板后下一击被重定向到旧节点（拖错节点/再双击又弹旧面板）；面板关闭后补发丢失的 release 让状态机干净收尾
- **拓扑 Ping 按钮用占位 IP**（“未获取”字符串被当可用地址），改为不可用 IP 不出 Ping 入口
- **终端换口后陈旧 MAC 抢占定位**：同 MAC 多端口条目“最后写的赢”，改为优先链路 UP 端口
- **配置转换保真**：`undo trunk permit vlan 1` 误加、secondary IP 覆盖 primary、NULL0 黑洞路由被丢弃、`vlan batch` 全量展开不压缩（均改为忠实转换 + 区间压缩）

## 使用说明

1. 选择设备品牌（华为/H3C/锐捷/迈普）
2. 点击"配置模板"选择预设场景（可选）
3. 在各标签页填写配置参数
4. 点击"验证配置"检查参数格式
5. 点击"生成配置"生成完整脚本
6. 导出文件或复制到剪贴板

### 华为与H3C配置差异

| 配置项 | 华为 | H3C |
|--------|------|-----|
| 进入系统视图 | `system-view` | `system-view` |
| 设备命名 | `sysname` | `sysname` |
| VLAN接口 | `interface Vlanif10` | `interface Vlan-interface10` |
| 端口聚合 | `interface Eth-Trunk1` | `interface Bridge-Aggregation 1` |
| SSH服务 | `stelnet server enable` | `ssh server enable` |
| 用户权限 | `level 15` (0-15) | `level 3` (0-3) |
